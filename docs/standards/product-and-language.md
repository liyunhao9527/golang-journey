# 产品与文案规范

## 产品定位

Golang Journey 是面向 JavaScript / TypeScript 开发者的 Go 对照课程。它不从零解释编程，而是帮助读者把已有经验迁移为准确、惯用、可运行的 Go。

页面的核心任务是让读者快速回答：

1. 这个概念在两种语言中有什么相同点？
2. Go 的约束或惯用写法有什么不同？
3. 我如何通过运行代码或完成练习验证理解？

## 语气

- 像有经验的同事讲解迁移：直接、具体、平等。
- 先说结论，再解释原因和边界。
- 技术判断区分“语法合法”“惯用写法”和“编译错误”。
- 避免口号、拟人化系统术语和不承担信息的英文标签。
- 中文标题使用全角冒号；代码、命令和 API 名称保留原始形式。

## 固定术语

| 用途 | 统一写法 |
|---|---|
| 课时学习结果 | 本课目标 |
| 语言共同机制 | 相同点 |
| 语言规则差异 | 不同点 |
| 实际编码任务 | 动手练习 |
| 累积回忆任务 | 阶段复习 |
| 即时反馈 | 正确 / 不对，再想想 |
| 资料区域 | 参考资料 |
| 首页入口 | 开始学习 / 继续学习 / 回顾本课 |

## 标题规则

- H1 只写当前主题，例如“控制流”“变量与类型”。
- 课时眉题写“第 N 课 / 分类”，例如“第 3 课 / 语法基础”。
- 速查眉题写“速查 NN / 主题”。
- H2 直接说明本节知识，例如“for：一个关键字，三种循环”。
- 标题中出现语言关键字时保留原大小写，例如 `if`、`for`、`switch`。

## 对照文案

每组双语代码之间必须有一条解释轨：

```html
<div class="translation-rail" aria-label="Go 与 TypeScript 的异同">
  <span><b>相同点</b>两种语言都……</span>
  <span><b>不同点</b>Go……，TypeScript……</span>
</div>
```

两条说明都要表达具体机制。不能只写“写法相似”“语法不同”。

## 完成标准

一段新文案完成时，应能回答：它告诉读者做什么、为什么这样做、如何确认自己做对了吗？缺少其中一项时，继续补充示例、练习或反馈。
