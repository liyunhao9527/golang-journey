# 课程内容规范

## 每课结构

每个课时按照下面的学习顺序组织：

1. 课时标题、简短导语和可验证的本课目标。
2. 3 至 5 个核心章节，每章只引入一组相关概念。
3. 必要的 Go / TypeScript 对照与“相同点 / 不同点”解释。
4. 可运行的完整示例或明确指向 `demos/` 的示例文件。
5. 动手练习，给出可观察的成功条件。
6. 阶段复习，用已有知识从空文件独立完成任务。
7. 小测验，答错后允许继续选择，答对后解释原因。
8. 参考资料，优先指向 Go 官方文档和课程内相关页面。

课时较短时可以省略阶段复习，但不能省略动手练习、反馈和参考资料。

## 讲解顺序

- 编写前列出本节的前置知识、基本操作、边界条件和验证练习；前置知识必须已在前文讲解，或在当前示例旁补充说明。
- 按“最小完整程序 → 常用变化 → 边界与错误 → 惯用写法 → 独立练习”推进。先覆盖读者完成本课目标必需的基本操作，再介绍语法技巧。
- 例如讲解 `if` 时，先覆盖布尔条件、`if/else`、多条件组合、括号分组和短路求值，再介绍初始化语句与作用域。
- 先展示 Go，再展示 TypeScript 对照。
- 对照的作用是解释迁移关系，不是为了凑齐两段代码。
- 新概念首次出现时，在正文给出最小完整、可运行的程序。后续局部变化可以使用明确标注上下文的片段；demo 链接作为补充，不能代替首次完整示例。
- 涉及 Unicode、零值、作用域、并发等容易误解的主题时，明确数据表示和边界条件。

## 代码示例的完整性

每个代码块都必须让读者在复制之前明确它属于哪一类。通过紧邻的正文、代码标签或注释说明；同一完整示例的说明可由相邻代码块共用。

| 类型 | 必须提供的上下文 | 完成条件 |
|---|---|---|
| 完整程序 | 文件名、从哪个目录运行、准确命令、预期输出或行为 | 复制到指定文件即可运行，所有导入、变量、函数和依赖齐全 |
| 局部片段 | 插入或替换的具体文件、函数或已展示代码位置，以及依赖的声明 | 读者按说明组合后即可运行，无需猜测或自行补代码 |
| 语法示意 | 明确标为“语法示意，不可直接运行”，解释占位符含义 | 仅用于概括语法；首次讲解仍提供完整程序 |
| 命令或输出 | 命令的工作目录与前置条件，或输出所对应的命令和输入 | 命令实际执行，输出与执行记录一致 |
| 错误示例 | 明确标为“预期编译错误”或“预期运行错误”，说明触发原因与修复方式 | 实际触发所述错误，修复后的版本也通过验证 |

- Go 完整可执行程序包含 `package main`、实际使用的导入和 `func main()`；多文件或模块示例提供完整文件结构与初始化步骤。
- `:=` 短变量声明和 `if`、`for` 等执行语句放在函数体内。讲解包级变量时使用 `var`，明确与函数内声明的区别。
- 缩略片段不能冒充完整程序。作为省略标记的 `...`、未定义的 `compute()`、`use()` 等占位内容只用于已标注的语法示意；可运行示例提供实际定义。
- Go 与 TypeScript 分别遵守各自的程序结构；Go 的函数外壳不能因为 TS 可以在脚本顶层执行而省略。
- 速查页可以使用片段或语法示意，但也必须标明上下文，并链接到课程中的对应完整示例。

## 技术表述与对照

- 将语言规则、惯用风格和项目约定分开表述。例如“`:=` 不能用于包级声明”是语言规则，“通常省略 `if` 条件外层括号”是风格建议。
- 对“必须”“不能”“总是”等结论写明适用范围，并以 Go 官方规范或文档核对；单个运行结果只证明该示例的行为。
- 相似语法的对照须检查类型、返回值、作用域、求值顺序和错误行为中与本节相关的差异。仅在明确限定范围后使用“相同”。
- 示例引入尚未教过的语法、类型或 API 时，就地解释或链接到明确的前置课时；优先选择读者已学会的写法。
- 语言设计原因需要来源支持；没有来源时，只描述可确认的规则和实际影响。

## 演示代码与页面验证

1. 列出本次新增或修改的代码块，按上表分类，为可执行示例找到对应 demo 或验证文件；语法示意核对官方语法和所链接的完整示例，输出块与对应执行记录核对。
2. 从最终 HTML 中提取代码文本并解码 HTML 实体。完整程序直接保存运行；局部片段只按页面已经写出的说明组合运行。验证过程中如需额外补充声明或步骤，先将它们补回页面。
3. 对 Go 执行对应的运行或编译命令；对 TypeScript 执行项目采用的类型检查，并运行涉及输出或行为的示例。错误示例在临时文件中单独验证。
4. 实际核对输出、分支选择和错误原因。条件示例至少覆盖成立与不成立；涉及边界、短路或优先级时，执行能区分正确与错误写法的输入。只检查退出码不足以确认教学结论。
5. 对照页面、demo、注释、练习参考答案和期望输出，确保逻辑一致；演示文件的函数封装和显示缩进可以不同，但页面须交代执行上下文。

验证记录至少包含页面及小节、示例类型、运行命令、输入和实际结果，可记在任务工作记录或交付说明中。仅运行 demo、通过 HTML 检查或看到语法高亮，不代表页面示例已验证。

可运行 Go 源文件采用 `gofmt`；网页显示缩进遵循[视觉系统](visual-system.md)。个人实验保留在对应 `sandbox/` 下，预期失败的验证放在临时文件中，不覆盖基准 demo 或读者已有实验。

## 练习与反馈

每个练习至少包含：

- 要修改或创建的对象；
- 明确的操作要求；
- 可观察结果，例如终端输出、编译错误或测试结果；
- 折叠的参考答案或修正说明。

参考答案解释关键决策，不只给最终代码。故意触发错误时，准确区分预期错误与恢复步骤。

## 测验

- 每道题只有一个明确正确答案。
- `data-explain` 解释正确答案成立的原因。
- 反馈区域保留 `aria-live="polite"`。
- 答错选项禁用，但其余选项仍可继续选择；答对后全部禁用。
- 选项文字本身表达答案，不能只靠颜色或图标区分。

## 资料来源

优先级如下：

1. Go 官方语言规范、Tour、标准库文档与官方博客；
2. 项目已采用的 Go by Example、Learn Go with Tests、Exercism；
3. 其他资料只作补充，并核对发布日期和 Go 版本。
