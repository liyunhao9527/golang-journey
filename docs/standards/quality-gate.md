# 质量门槛

课程、演示或界面改动只有满足本页检查才算完成。

## 内容

- 技术事实与 Go 官方文档或实际运行结果一致。
- 页面示例与 `demos/` 文件一致。
- 本课目标可以通过运行、输出、测试或编译结果验证。
- 每个语言对照都有具体的“相同点 / 不同点”。
- 练习包含完成条件和参考反馈。
- 测验解释原因，而不只报告对错。

## 结构与视觉

- 页面使用正确的 Body variant 和 `TS→GO` 品牌标记。
- 课时章节或速查卡片间距为 `16px`。
- Go 代码在上，TypeScript 代码在下。
- 图标只来自本地 IconPark sprite，且附随可访问文字。
- 375、768、1024、1440px 下没有页面级横向溢出。
- 移动端交互目标至少 44px。
- 浅色、暗色、键盘焦点和减少动态效果状态可用。
- 宽代码和表格的滚动限制在组件内部。

## 功能

- 所有导航链接与页面锚点有效。
- 代码块完成语法高亮，并保留语言 class。
- 测验支持“答错后继续尝试，答对后显示解释”。
- 测验反馈保留 `aria-live="polite"`。
- 浏览器控制台没有页面自身产生的错误或警告。

## 必跑检查

在仓库根目录执行：

```powershell
& tests/course-quality.ps1
& tests/syntax-highlighting.ps1
node --check assets/quiz.js
node --check assets/highlight-init.js
git diff --check
```

涉及 Go 或 TypeScript demo 时，再运行对应示例与类型检查。涉及页面结构或 CSS 时，在真实浏览器检查三类代表页面：课程首页、一个课时页和一张速查页。

## 交付说明

交付时只报告：

- 修改覆盖了哪些页面或内容；
- 关键设计或教学决策；
- 实际执行过的验证及结果；
- 尚未解决且会影响使用的问题。

不要把仅靠静态阅读得出的判断写成“已验证”。
