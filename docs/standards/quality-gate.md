# 质量门槛

课程、演示或界面改动只有满足本页检查才算完成。

## 内容

- 逐项核对[课程内容规范](course-content.md)中的讲解顺序、示例完整性、技术表述和页面验证要求；任一新增或修改示例缺少其类型要求的上下文或验证证据，均不算完成。
- 逐个本课目标检查：是否已教授所需基础操作，读者能否仅凭页面给出的信息完成练习；发现缺口时先补讲解与反馈。
- 本课目标可以通过运行、输出、测试或编译结果验证。
- 每个语言对照都有具体的“相同点 / 不同点”。
- 练习包含完成条件和参考反馈。
- 测验解释原因，而不只报告对错。

## 结构与视觉

- 页面使用正确的 Body variant 和 本地 Go 官方品牌标志。
- 课时章节或速查卡片间距为 `16px`。
- Go 代码在上，TypeScript 代码在下。
- 图标只来自本地 IconPark sprite，且附随可访问文字。
- 375、768、1024、1440px 下没有页面级横向溢出。
- 移动端交互目标至少 44px。
- 浅色、暗色、键盘焦点和减少动态效果状态可用。
- 宽代码和表格的滚动限制在组件内部。

## 功能

- 所有导航链接与页面锚点有效。
- 代码块完成语法高亮，并保留语言 class。
- 测验支持“答错后继续尝试，答对后显示解释”。
- 测验反馈保留 `aria-live="polite"`。
- 浏览器控制台没有页面自身产生的错误或警告。

## 必跑检查

在仓库根目录执行：

```powershell
& tests/course-quality.ps1
& tests/syntax-highlighting.ps1
node --check assets/quiz.js
node --check assets/highlight-init.js
git diff --check
```

涉及页面代码示例或 Go / TypeScript demo 时，再执行课程内容规范中的页面提取、组合运行、分支验证与类型检查。涉及页面结构或 CSS 时，在真实浏览器检查三类代表页面：课程首页、一个课时页和一张速查页。

## 失败与完成判定

- 新增改动造成的失败必须修复后再交付为完成；缺少运行环境或验证未执行时，明确列为未验证项。
- 发现既有失败时，核对它是否在本次修改前已存在，报告具体检查与影响；既有失败不算通过，也不能据此跳过本次改动的验证。
- 文档规范改动检查入口链接、规则冲突和 `git diff --check`；它本身不等于完成全站内容审查。仅修改规范且未改课程、示例或界面时，无需运行无关的 demo 或浏览器检查。

## 交付说明

交付时只报告：

- 修改覆盖了哪些页面或内容；
- 关键设计或教学决策；
- 实际执行过的验证及结果；
- 尚未解决且会影响使用的问题。

不要把仅靠静态阅读得出的判断写成“已验证”。
