# 首页视觉设计：从 Rust 的阅读节奏到 Go

## Rust 首页为什么显得克制

参考本地 rust-journey/assets/home.css 与浏览器实际页面。它的质感来自稳定的比例和有限的强调色。

| 维度 | Rust 实现 | 原 Go 首页的问题 | 本次处理 |
| --- | --- | --- | --- |
| 背景 | 纸白 #f7f6f2，表面 #fffefa | 冷灰背景上反复叠白色框，层级过多 | 冷白 #f5f7f7 为连续底色，只保留必要容器 |
| 强调 | 锈红 #a04325，仅用于行动和重点 | 青色边框、标题、按钮同时竞争 | 低饱和青色 #287887，集中于行动、课程重点和状态 |
| 文字 | 墨色 #292823 与灰色 #69665e | 窄体粗标题过大，正文也偏重 | Avenir Next 与中文系统无衬线，标题 600 字重，正文 400 |
| 字号 | H1 最大 41px，H2 最大 33px，正文 15px | H1 最大 80px，显著压过正文 | H1 最大 46px、H2 最大 32px，正文 15px / 1.85 |
| 空间 | 最大宽 1200px，章节间隔约 82px | 大卡片内部和外部间距重复，页面密集 | 最大宽 1200px，桌面章节 80px、手机 52px |
| 主视觉 | 完整源码与错位命令说明 | 深色大框承载纯文字路线，像占位面板 | 第一课完整 Go 源码与真实输出；路线留在下方 |
| 章节结构 | 近期课程不对称布局，路线横排，资料主次分明 | 多个区域使用同类卡片 | 重点课程块、开放路线、项目行、主教材与资料列表 |

Rust 的暖纸与锈红是其语言品牌的一部分。Go 借鉴比例和构图，使用统一冷色体系，保留自己的青色。首页与目录共享样式，课时和速查仍保留原有阅读组件。

## 构图方案与自检

采用左对齐和不对称分栏：

```text
品牌                                  课程 / 速查 / 开始学习

学习对象与两行标题                     hello.go 完整程序
说明 + 第一课入口                       运行命令与输出

学习约定                               练习方法

选课说明                 第一课重点块
                         最近课程简要入口

阶段编号     主题与内容                  过关证据

项目类型     项目目标                    验收要求

主教材                                其余参考资料
```

设计复核时去掉了原先整块包裹章节的容器，把边框留给代码、首课和主教材。项目不是强制先后顺序，因此取消项目的装饰编号；阶段路线具有学习先后关系，保留编号。标题全文使用同一颜色；等宽字体只用于真实代码、命令和阶段序号。

不引入框架、远程字体或动画库。现有纯静态站点和本地 IconPark 规范优先于技能的默认技术栈。入口仅有代码区一次轻微入场、按钮悬停及按压反馈，减少动态效果时关闭。没有需要伪造的加载、空数据或提交状态。

## 实现入口

- index.html：首页语义结构、Go 代码与运行说明。
- lessons/0000-course-list.html：一致的目录色彩、字阶和表格。
- assets/home.css：首页与目录的公共组件和明暗 token。
- assets/style.css：移除上一版只供首页使用的尾部规则；既有教学样式保留。
- docs/standards/visual-system.md：入口视觉规范，说明与课时样式的职责。

## 验证

- 从最终 index.html 提取完整 Go 代码，临时保存为 hello.go，执行 go run hello.go，输出为 Hello, Go!。
- 首页与课程目录的本地资源、HTML 锚点和唯一 ID 检查通过。
- node tests/browser-layout.mjs：四种屏宽的首页、第四课、第四张速查布局、高亮与答错后重试的测验反馈通过。
- 额外使用独立 Chrome 标签逐页检查：首页、目录、第四课与第四张速查，在 375、768、1024、1440px 与浅色、暗色下，检查横向溢出、高亮和导航目标；首页手机第一课按钮在首屏，Tab 可聚焦跳转链接。
- 人工复核完整首页、完整目录、桌面浅色和手机暗色截图。
- node --check assets/quiz.js、node --check assets/highlight-init.js 与 git diff --check 通过。
