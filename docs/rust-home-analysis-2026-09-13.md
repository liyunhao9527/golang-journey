# Rust 首页对照分析与 Go 落地

## 结论

Rust 首页把“适合谁、现在学什么、之后怎么学、如何证明掌握”串成完整学习入口。Go 原首页只展示四节课程，而课程目录已包含六节，既缺少后续路线，也存在内容漂移。本次借鉴 Rust 的信息结构，沿用 Go 的冷灰纸面、青色强调和共享组件。

分析依据：本地 rust-journey 的 index.html、courses.html、assets/home.css、assets/courses.js、assets/course-ui.js、ROADMAP.md 和 .agents/skills/；Go 的首页、课程目录、MISSION.md 与现有规范。Rust 页面行为分析来自源码阅读；浏览器验收针对本次 Go 改动。

## 首页内容与页面结构

| Rust 的设计 | 作用 | Go 的落地 |
| --- | --- | --- |
| 导航区：全部课程、路线、资料、开始或继续学习 | 让新读者和回访读者各有入口 | 保留课程、速查、开始学习导航，首屏增加路线入口 |
| 双栏首屏：受众与行动按钮 / 源码和命令示意 | 先交代适合谁，再展示学习对象 | 左栏交代 TS 经验迁移，右栏概览 Go 五阶段；移动端直接突出开始学习 |

Rust 的首页与独立目录分工明确。目录提供关键词搜索、阶段筛选、开放状态筛选；共享课程数据维护课程计数和链接，浏览器本地存储保存最近访问课时。这个记录表示访问位置，不能作为掌握证据。

Go 当前只有六节已开放课，本次保留静态完整目录，保证无脚本也能选课；尚未移植搜索和最近访问记录。课程增多后，可以借鉴 Rust 的单一课程数据来源，再生成静态目录并渐进增强筛选。当前新增课程时须同步首页数量、目录与路线状态。

## 课程规划取舍

Rust 以所有权、借用和生命周期为语言主轴，项目覆盖 CLI、服务端和 WASM。Go 的已有学习目标是系统掌握语言、并发、标准库 HTTP，并能阅读开源代码，因此路线调整为：

1. 程序与基础语法。
2. 数据与值的传递。
3. 类型、组合与错误。
4. 并发与取消。
5. 标准库与工程实践。

沿用短课、语言对照、检索练习与阶段验收。每个阶段按实际表现推进，不规定周数。函数先于方法和接口，错误与测试先于工程项目；并发先用最小任务，HTTP 检查项目等客户端知识齐备后再开始。

保留 MISSION.md 中“先系统学习，再确定方向”的目标。三个项目是可选实践方向；不照搬 Rust 的 WASM 目标，也不采用 Rust 项目阶段停止 TS 对照的规则。

完整顺序与项目验收见 [ROADMAP.md](../ROADMAP.md)。本次没有新增未来课时正文，也没有把计划标成已开放。
