声明变量与常量：var、:=、const

本页 Go 代码块均为独立完整程序：每次保存到练习目录的 main.go，在该目录执行 go run main.go。TypeScript 块各自保存为 main.ts，用 tsc --strict --noEmit --target es2022 main.ts 检查，再用支持类型擦除的 Node 运行 node main.ts。命令中特别写出 demos/ 路径时，从仓库根目录执行。

下面区分三种变量声明写法和一种常量声明，对照 TS 的 let/const:

Go含义TS 对照
var x string = "a" 声明并显式标注类型 let x: string = "a"
var x = "a" 声明,类型由编译器推断 let x = "a"
x := "a" 短声明:声明 + 推断,函数内最常用 TS 没有等价写法;记住":= = let + 推断"
const x = "a" 编译期常量,不可重新赋值 const x = "a"

先分清三条规则：

  • := 只能用在函数内部。包级(顶层)只能写 var 或 const。
  • 变量声明后，类型固定：x := 1 之后写 x = "a" 会编译报错。TS 的 let x = 1 也是这个行为,Go 也有 any，但需要明确声明；本课使用具体类型。
  • 未使用的局部变量是编译错误(未使用的 import 同理)。TS 是否报告未使用变量取决于 noUnusedLocals 等编译选项和 lint 配置；Go 工具链会拒绝未使用的局部变量和导入。

先运行一个声明与零值示例

completed 从 1 增加到 2；label 没有显式赋值，打印带引号的空字符串。后面再解释零值规则。

Go / main.go

package main

import "fmt"

func main() {
  const pointsPerLesson = 10
  completed := 1
  completed += 1
  var label string
  fmt.Println(completed, completed*pointsPerLesson)
  fmt.Printf("%q\n", label)
}
相同点两段都把计数增加到 2，并算出 20 分。不同点Go 的 string 自动得到空字符串；TS 这里显式初始化为空字符串以得到相同输出。

TypeScript / main.ts

const pointsPerLesson = 10;
let completed = 1;
completed += 1;
let label: string = "";
console.log(completed, completed * pointsPerLesson);
console.log(JSON.stringify(label));

两行输出依次是 2 20 和 ""。completed 已经声明，更新它用 = 或 +=；不要在同一作用域写 completed := 2，因为左边没有新的变量。

Go 的 const 不是 TS 的只读变量

TS 的 const 表示“这个变量绑定不能重新赋值”,右侧仍可以是运行时才得到的对象或函数结果。Go 的 const 必须在编译期确定,只能表示布尔、数字、字符串等常量值;slice、map 和普通函数的运行结果不能作为常量；部分内置函数在特定条件下可产生常量，例如 len("Go")。

Go 还支持未类型化常量:例如 const n = 3 在真正赋给某个变量前不会过早固定成 int,因此可以在编译器确认值可表示的前提下用于不同数值类型。日常先记住:Go 的 const 是编译期值,不是 TS const 的一比一翻译。

遇到 declared and not used 时，先看变量是否遗漏了使用：需要观察它，就打印；需要参与计算，就接到计算里；确实不用，再删除声明。编译错误指出的是未使用的位置，不代表所有这类变量都应直接删掉。

零值:没有 undefined 的世界

TS 里声明不初始化,得到 undefined;Go 里声明不初始化,得到该类型的零值——每个类型都有自己固定的"默认值":

类型零值TS 对照
string""undefined
int / float640 / 0.0undefined（声明但未赋值；NaN 是另一种数值）
boolfalseundefined
零值为 nil 的类型(slice/map/指针等)nil(后续课程分别展开)接近 null,但行为并不相同

这意味着读取一个未显式初始化的 Go 变量时,结果总有明确规则,而不是得到 undefined。但零值有明确定义,不等于任何操作都安全:nil 指针解引用、向 nil map 写入仍会 panic。后续学习每种类型时,都要继续问一句:“它的零值能做什么?”

关键差异:TS 的 let s: string 之后直接读取,严格类型检查会报错;若绕过检查执行 JavaScript,运行时值是 undefined。Go 的 var s string 可以直接读取,得到 ""。如果业务必须区分“未提供”和“明确提供空字符串”,需要另建状态,常见方案包括额外布尔值或指针(后续课程展开)。

fmt.Printf 常用占位符

% 加字母是输出格式占位符,不是类型转换。它只决定传入的值如何显示,不会改变变量本身的类型:

占位符用途示例
%v默认格式,通用打印fmt.Printf("%v", x)
%+v结构体打印字段名和值fmt.Printf("%+v", user)
%T打印值的类型int
%d十进制整数42
%f浮点数3.140000
%t布尔值true
%s字符串hello
%q带引号的字符串或字符"hello"
%c把整数/rune 按 Unicode 字符显示A
package main

import "fmt"

func main() {
  n := 65
  fmt.Printf("%d %c\n", n, n) // 65 A
}

和 TS 对照:

Go

package main

import "fmt"

func main() {
  n := 65
  fmt.Printf("%d %c\n", n, n) // 65 A
  fmt.Printf("%T\n", n)         // int
}
相同点两种语言都能查看数值、字符和运行时类型 不同点Go 用格式化动词控制输出，TypeScript 通常调用对应方法

TypeScript

const n = 65;
console.log(n, String.fromCodePoint(n)); // 65 A
console.log(typeof n);                  // number

TS 的 console.log 通常直接接收值,不会像 Go 的 Printf 一样用 %d、%c 控制每个参数的显示格式;需要组合文本时可以使用模板字符串,例如 console.log(`${n} ${String.fromCodePoint(n)}`)。

显式类型转换:T(x)

已有数值变量在不同数值类型之间赋值时，需要显式转换。例如 int 和 float64 都表示数字,也必须明确写出目标类型:

package main

import "fmt"

func main() {
  var n int = 3
  var f float64 = float64(n)

  fmt.Printf("%T %v\n", n, n) // int 3
  fmt.Printf("%T %v\n", f, f) // float64 3
}

通用写法是 目标类型(值),也就是 T(x)。它会产生一个新值,不会改变原变量的类型——上面的 n 转换后仍然是 int。

浮点变量也可以转成整数。在本例数值可表示的范围内，小数部分向零截断，不是四舍五入：

package main

import "fmt"

func main() {
  price := 19.9
  whole := int(price)
  fmt.Println(whole) // 19
}

转换不等于解析。上面的 int(price) 将浮点变量转换为整数；直接写 int(3.8) 则是预期编译错误，因为常量 3.8 不能表示为整数。把 3.8 先保存到浮点变量，再转换该变量，才会截断小数。把字符串 "42" 读成数字要用 strconv.Atoi 或 strconv.ParseInt,不能写 int("42")。字符串解析会在后续处理输入时展开。

注意字符串拼接的区别：Go 中 "1" + 1 不能编译。明确写出转换,能让数值精度和数据含义的变化一眼可见。

对照代码:同一套声明,两种语言

完整可运行代码在 demos/02-variables/(vars.go / vars.ts),核心差异:

Go — 独立完整示例

package main

import "fmt"

func main() {
  var explicit string = "显式类型"
  var inferred = "类型推断"
  short := "短声明"
  fmt.Println(explicit, inferred, short)

  var s string // 零值 ""
  var n int    // 零值 0

  fmt.Printf("%q %d\n", s, n) // "" 0
}
相同点两种语言都支持显式类型与类型推断 不同点Go 提供零值和短声明，TypeScript 需要显式处理 undefined

TypeScript — 独立脚本

const explicit: string = "显式类型";
const inferred = "类型推断";
let short = "短声明";

let s: string | undefined = undefined;
let n: number | undefined = undefined;

console.log(s, n); // undefined undefined
# 在仓库根目录运行两个文件
go run demos/02-variables/vars.go
node demos/02-variables/vars.ts

这里的 TS 对照文件把变量显式写成 string | undefined 并初始化为 undefined,因此既能通过严格类型检查,又能观察 JavaScript 运行时值。直接写 let s: string 后读取,会被 TypeScript 拒绝。

动手练习

  1. 运行 go run demos/02-variables/vars.go,对照注释确认每一行的输出。
  2. 亲手触发一次编译错误:在 main() 里加一行 unused := 1,再运行。你会看到 declared and not used: unused——然后把这一行删掉。
  3. 猜一下再验证:var b byte = 'A' 然后 fmt.Printf("%T %d\n", b, b),输出是什么?(提示:byte 是 uint8 的别名)
  4. 先猜再运行:f := 8.75、n := int(f),然后打印 f、n 及各自的类型。确认转换产生了新值,且结果是截断而非四舍五入。

完成故意报错的练习后,记得撤销临时代码,让 vars.go 恢复为可运行的基准 demo。

练习参考答案与复原(先做完再看)
