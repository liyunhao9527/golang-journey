变量与类型:从 let/const 到 var/:=

预计 15 分钟 · 对照基线:TypeScript · 主源:A Tour of Go — Variables

本课胜利:能用三种方式声明变量,能脱口说出任意类型的零值——并亲手触发一次"未使用变量"的编译错误,理解 Go 对歧义的零容忍。

声明三兄弟:var / := / const

Go 的变量声明有四种写法,前三兄弟对应 TS 的 let/const:

Go含义TS 对照
var x string = "a" 声明并显式标注类型 let x: string = "a"
var x = "a" 声明,类型由编译器推断 let x = "a"
x := "a" 短声明:声明 + 推断,函数内最常用 TS 没有等价写法;记住":= = let + 推断"
const x = "a" 编译期常量,不可重新赋值 const x = "a"

三条铁律,和 TS 的直觉不太一样:

  • := 只能用在函数内部。包级(顶层)只能写 var 或 const。
  • 类型一旦确定,终身不变:x := 1 之后写 x = "a" 会编译报错。TS 的 let x = 1 也是这个行为,但 Go 没有 any 兜底——除非你显式声明。
  • 未使用的局部变量是编译错误(未使用的 import 同理)。TS 里这只是 ESLint 的一条 warning,Go 直接拒绝编译。

为什么?Go 的设计哲学是"零歧义、零容忍":没用的代码就是 bug 的温床。第一次被 declared and not used: x 卡住时别慌——删掉那行就好了。

零值:没有 undefined 的世界

TS 里声明不初始化,得到 undefined;Go 里声明不初始化,得到该类型的零值——每个类型都有自己固定的"默认值":

类型零值TS 对照
string""undefined
int / float640 / 0.0undefined(JS 里是 NaN/undefined 混杂)
boolfalseundefined
引用类型(slice/map/指针等)nil(第 4 课展开)null

这意味着 Go 代码里不存在"用了未初始化的变量"这种运行时错误——每个变量从出生起就有一个合法值。这也是为什么 Go 程序里 undefined 这个词根本不出现。

关键差异:TS 的 let s: string 之后读 s,严格模式下编译报错、运行时是 undefined;Go 的 var s string 之后读 s,安全地得到 ""。代价是:Go 里你永远无法区分"没赋值"和"赋值成了空字符串"——Go 认为这个区分不值得(需要的话可以用指针,第 5 课讲)。

基础类型:一张表对照完

boolboolean
int, int8…int64, uint…numberJS 的 number 只有一个(浮点);Go 显式区分位数和符号,int = 平台原生字长

用 %T 打印类型:fmt.Printf("%T", x) 输出 x 的类型(对照 TS 的 typeof)。注意 rune 打印出来是 int32,因为它就是 int32 的别名。

显式类型转换:T(x)

Go 不会在不同类型之间自动转换。即使 int 和 float64 都表示数字,也必须明确写出目标类型:

var n int = 3
var f float64 = float64(n)

fmt.Printf("%T %v\n", n, n) // int 3
fmt.Printf("%T %v\n", f, f) // float64 3

通用写法是 目标类型(值),也就是 T(x)。它会产生一个新值,不会改变原变量的类型——上面的 n 转换后仍然是 int。

反向转换也可以,但小数部分会被直接截掉,不是四舍五入:

price := 19.9
whole := int(price)
fmt.Println(whole) // 19

转换不等于解析。int(3.8) 是数字类型之间的转换;把字符串 "42" 读成数字要用 strconv.Atoi 或 strconv.ParseInt,不能写 int("42")。字符串解析会在后续处理输入时展开。

这和 JS/TS 的隐式强制转换不同:Go 中 "1" + 1 不能编译。明确写出转换,能让数值精度和数据含义的变化一眼可见。

对照代码:同一套声明,两种语言

完整可运行代码在 demos/02-variables/(vars.go / vars.ts),核心差异:

Go — vars.go(节选)

var explicit string = "显式类型"
var inferred = "类型推断"
short := "短声明"

var s string // 零值 ""
var n int    // 零值 0

fmt.Printf("%q %d\n", s, n) // "" 0

TypeScript — vars.ts(节选)

const explicit: string = "显式类型";
const inferred = "类型推断";
let short = "短声明";

let s: string; // undefined
let n: number; // undefined

console.log(s, n); // undefined undefined
# 两个文件输出对照
cd demos/02-variables && go run vars.go
cd demos/02-variables && node vars.ts

练习(动手,5 分钟)

  1. 运行 go run vars.go,对照注释确认每一行的输出。
  2. 亲手触发一次编译错误:在 main() 里加一行 unused := 1,再运行。你会看到 declared and not used: unused——然后把这一行删掉。
  3. 猜一下再验证:var b byte = 'A' 然后 fmt.Printf("%T %d\n", b, b),输出是什么?(提示:byte 是 uint8 的别名)
  4. 先猜再运行:f := 8.75、n := int(f),然后打印 f、n 及各自的类型。确认转换产生了新值,且结果是截断而非四舍五入。
第 3 步期望输出(先猜完再看) 
uint8 65

字符 'A' 的码点是 65;%T 显示别名背后的真实类型 uint8,和 rune 显示 int32 同理。
