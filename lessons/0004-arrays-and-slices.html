数组：长度属于类型，赋值会复制

先看结论：[3]string 是“恰好 3 个字符串”的数组类型，长度不能在运行时改变。[3]string 与 [4]string 是不同类型。数组变量保存整份数组值，因此赋值给另一个变量时会复制全部元素。

下面两段都是完整程序。把 Go 代码保存为 main.go，在该文件目录运行 go run main.go；把 TypeScript 代码保存为 main.ts，用本机 TypeScript 运行环境执行。两段程序故意展示不同的默认赋值语义。

Go / main.go

package main

import "fmt"

func main() {
  languages := [3]string{"TypeScript", "Go", "Rust"}
  copied := languages
  copied[0] = "JavaScript"

  fmt.Println("original:", languages)
  fmt.Println("copied:  ", copied)
}
相同点两种语言都能在类型层表达三个字符串槽位 不同点Go 数组赋值复制元素；TypeScript 数组或 tuple 赋值复制的是引用

TypeScript / main.ts

const languages: [string, string, string] = [
  "TypeScript",
  "Go",
  "Rust",
];
const alias = languages;
alias[0] = "JavaScript";

console.log("original:", languages);
console.log("alias:   ", alias);

Go 程序输出：

original: [TypeScript Go Rust]
copied:   [JavaScript Go Rust]

TypeScript 中若想得到独立的浅副本，要显式写 const copied = [...languages]。Go 日常处理长度会变化的序列时通常不直接用数组，而是使用下一节的 slice。

slice：一段底层数组的描述符

[]string 是 slice 类型，方括号内没有长度。slice 自身可以理解为一份小描述符：它记录当前可见片段、长度和容量，并让你访问某个底层数组。slice 赋值会复制描述符，不会复制元素；两个 slice 因此可能共享同一份存储。

下面是完整程序，可保存为 main.go 并运行 go run main.go：

Go

package main

import "fmt"

func main() {
  languages := []string{"TypeScript", "Go", "Rust"}
  view := languages[1:3]
  view[0] = "Golang"

  fmt.Println("slice:", languages)
  fmt.Println("view: ", view)
}
相同点两种语言都用“起点包含、终点不包含”的区间 不同点Go 切片表达式共享元素存储；TypeScript 的 slice() 返回浅拷贝

TypeScript

const languages = ["TypeScript", "Go", "Rust"];
const rangeCopy = languages.slice(1, 3);
rangeCopy[0] = "Golang";

console.log("array:     ", languages);
console.log("range copy:", rangeCopy);

Go 的 view[0] 和 languages[1] 是同一个底层数组元素，所以 Go 输出 slice: [TypeScript Golang Rust]。TypeScript 的 slice(1, 3) 会创建一个新数组，修改 rangeCopy 不会替换原数组槽位。

零值 slice 可以直接 append

slice 延续了第 2 课的零值模型。未初始化的 slice 零值是 nil，其长度和容量都是 0；读取长度、range 遍历以及 append 都可安全使用。注意：这不代表对 nil slice 的任何操作都安全，直接访问 numbers[0] 仍会越界 panic。

下面是 main 函数体内的局部片段，可替换上一段 Go 程序的函数体：

var numbers []int
fmt.Println(numbers == nil, len(numbers), cap(numbers))

numbers = append(numbers, 42)
fmt.Println(numbers)
true 0 0
[42]

[]int{} 则是非 nil 的空 slice，长度同样是 0。多数追加和遍历代码不需要区分两者；当 JSON 等外部格式区分 null 与空数组时再明确选择。

len、cap 与 append：可见长度不等于容量

  • len(s)：当前可以索引和遍历的元素数。
  • cap(s)：从 slice 起点到底层数组末尾，最多可延展到的元素数。
  • append(s, value)：返回扩展后的 slice，必须接住返回值。

Go / main 函数体内

topics := make([]string, 0, 3)
topics = append(topics, "变量", "控制流")

fmt.Println(topics)
fmt.Println(len(topics), cap(topics))
相同点两种写法都在序列末尾加入元素 不同点Go 的 append 返回 slice；TypeScript 的 push 原地修改数组并返回新长度

TypeScript / 脚本顶层

const topics: string[] = [];
const newLength = topics.push("变量", "控制流");

console.log(topics);
console.log(newLength);

make([]string, 0, 3) 创建长度 0、容量 3 的 slice；三个槽位已经分配，但当前还不能用索引访问。前两次追加可以复用这份容量。

为什么必须写回？容量足够时，append 会复用底层数组；容量不足时，它会分配新数组并返回指向新存储的 slice。调用者不能依赖某一次追加究竟走哪条路径，需要更新原变量时写 s = append(s, value)；也可以把返回值保存到另一个变量，但不能忽略返回结果。

完整的容量演示在 arrays_slices.go 的 demoAppendCapacity。从仓库根目录运行：

go run demos/04-arrays-slices/arrays_slices.go

其中关键输出如下。第一次追加仍在容量 3 内，所以旧视图看到修改；第二次追加超出容量，返回的新 slice 与旧视图分离：

within capacity: [JavaScript Go Rust]
after growth:    [TS Go Rust Python]
old storage:     [JavaScript Go Rust]
动手验证：如果忽略 append 的返回值呢？

在 sandbox 中运行下面这个完整的预期编译错误程序。编译器会报告 append(topics, "slice") (value of type []string) is not used，因为追加结果没有被使用。

package main

import "fmt"

func main() {
  topics := make([]string, 0, 1)
  append(topics, "slice")
  fmt.Println(topics)
}

恢复步骤：改成 topics = append(topics, "slice")，再次运行应成功输出 [slice]。

make + copy：需要独立数据时明确复制

cloned := original 只复制 slice 描述符。要复制元素，先用 make 创建目标长度，再用 copy 搬运。copy(dst, src) 返回实际复制的元素数，即两边长度的较小值。

Go / main 函数体内

original := []int{1, 2, 3}
cloned := make([]int, len(original))
copied := copy(cloned, original)
cloned[0] = 99

fmt.Println(copied)
fmt.Println(original)
fmt.Println(cloned)
相同点两种写法都创建新的序列容器并浅复制元素 不同点Go 先分配目标 slice 再 copy；TypeScript 常用展开语法一步完成

TypeScript / 脚本顶层

const original = [1, 2, 3];
const cloned = [...original];
cloned[0] = 99;

console.log(original);
console.log(cloned);

这里的整数副本彼此独立。对于复杂元素，两种语言的这种写法都只做浅复制：元素如果自身包含 map、slice、对象或其他共享数据，复制外层序列并不会递归复制内部数据。

练习参考答案与关键解释 
package main

import "fmt"

func main() {
  topics := []string{"Go", "并发", "HTTP"}

  backup := make([]string, len(topics))
  copy(backup, topics)

  today := topics[:2]
  today[1] = "slice"
  topics = append(topics, "测试")

  fmt.Println("topics:", topics)
  fmt.Println("today:", today)
  fmt.Println("backup:", backup)
  fmt.Println("length:", len(topics))
}

today 与 topics 共享前两个元素，所以修改会联动；backup 的元素已经复制到新底层数组。append 的返回值写回后，topics 才拥有长度 4。

阶段复习：从空文件重建前三课

不回看答案，再写一个程序：用 var 声明 nil slice，通过 for 把 1 到 5 依次 append 进去，再用 range 和 if 只打印偶数。成功输出是两行：2 和 4。

阶段复习参考答案 
package main

import "fmt"

func main() {
  var numbers []int
  for i := 1; i <= 5; i++ {
    numbers = append(numbers, i)
  }

  for _, number := range numbers {
    if number%2 == 0 {
      fmt.Println(number)
    }
  }
}

这里同时复习了零值、三段式 for、range、_、if 和取模。nil slice 可直接 append，因此无需先写 make。
